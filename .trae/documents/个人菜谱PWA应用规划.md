# 个人菜谱 PWA 应用规划

## 一、总结

构建一个**移动优先的 PWA 网页应用**，用于管理个人菜谱、记录做菜笔记、每日菜单打卡。数据存储在本地浏览器（IndexedDB），支持一键导出/导入 JSON 备份。新增菜品时提供"抖音链接 → 提示词辅助"工作流，配合豆包等 AI 工具快速提取做法。

**核心价值**：手机浏览器打开即用，可添加到主屏幕像 App 一样使用，离线可用，无需服务器。

## 二、当前状态分析

- 工作目录 `d:\hll\self\食谱与菜单` 为空，全新项目
- 无历史代码、无依赖、无配置文件
- 用户提供了约 50+ 道菜的初始清单（带 ✔ 标记表示已做过）
- 营养目标（蛋白质 105g/脂肪 45g/碳水 130g）仅作参考展示，不做计量跟踪

## 三、技术栈决策

| 项目 | 选择 | 理由 |
|------|------|------|
| 框架 | 原生 HTML/CSS/JS | 无构建步骤，部署简单，GitHub Pages 直接托管 |
| 存储 | IndexedDB（Dexie.js 封装） | 支持大容量（照片），比 localStorage 更适合 |
| PWA | manifest.json + Service Worker | 可安装到主屏幕，离线可用 |
| 路由 | hash 路由（#/, #/dish/:id 等） | 无需服务器配置 |
| UI | 移动优先响应式，底部 Tab 导航 | 手机操作方便 |
| 依赖 | Dexie.js（CDN） | 唯一外部依赖，简化 IndexedDB 操作 |

## 四、数据模型

### Dish（菜品）存储于 `dishes` 表
```javascript
{
  id: auto,              // 自增主键
  name: "豆角肉沫",       // 菜名
  category: "荤菜",       // 分类：荤菜/素菜/汤/凉菜/主食/其他
  cooked: true,          // 是否做过（对应 ✔）
  photo: null,           // Base64 图片（后续上传）
  douyinUrl: "",         // 抖音视频链接
  ingredients: "",       // 食材清单
  method: "",            // 做法步骤
  notes: [               // 做菜笔记（多次记录）
    { date: "2026-08-13", content: "盐少放点，豆角要多炒" }
  ],
  createdAt: timestamp,
  lastCookedAt: timestamp | null
}
```

### MealLog（每日菜单）存储于 `meals` 表
```javascript
{
  id: auto,
  date: "2026-08-13",    // YYYY-MM-DD
  dishIds: [1, 3, 5],    // 当天吃的菜品 ID
  note: ""               // 备注（可选）
}
```

## 六、功能与界面设计

### 底部 Tab 导航（4个标签）

#### Tab 1: 菜谱（首页）
- 顶部搜索框（按菜名搜索）
- 筛选标签：全部 / 已做过 / 没做过 / 按分类（荤菜/素菜/汤/凉菜/主食）
- 菜品列表（卡片式）：菜名 + 缩略图（如有）+ 状态标记(✔) + 分类标签
- 点击菜品 → 进入详情页

#### 菜品详情页
- 菜品图片（如有，否则占位符）
- 菜名 + 分类 + 状态(做过/没做过)
- 抖音视频链接（可点击跳转）
- 食材清单
- 做法步骤
- **做菜笔记区域**：按时间倒序展示历史笔记
- **"记录今日做法"按钮**：弹出文本框，输入本次做菜心得，保存后添加到笔记历史
- 编辑按钮：修改菜品信息

#### Tab 2: 新增菜品
- 表单：菜名、分类、是否做过、食材、做法、抖音链接
- **"从抖音添加"辅助功能**：
  1. 粘贴抖音视频链接
  2. 点击"生成提示词"→ 自动复制一段预置提示词到剪贴板
  3. 显示提示："已复制提示词，请打开豆包粘贴链接和提示词，获取做法后粘贴到下方"
  4. 做法 textarea 中可直接粘贴 AI 返回的总结
- 图片上传（可选，后续补充）
- 预置提示词模板：
  ```
  请根据这个抖音视频链接：{链接}
  帮我提取这道菜的做法，包括：
  1. 菜名
  2. 所需食材和用量
  3. 详细步骤
  4. 关键技巧/注意事项
  请用简洁的文本格式输出。
  ```

#### Tab 3: 每日菜单
- 日期选择器（默认今天）
- 当天已选菜品列表（可移除）
- "添加菜品"按钮 → 从菜品列表多选
- 备注（可选）
- 历史记录列表（按日期倒序）

#### Tab 4: 我的
- 统计信息：总菜品数、已做过数、没做过数、本月做菜次数
- 营养目标参考展示（蛋白质 105g/脂肪 45g/碳水 130g/天）—— 仅展示，不计算
- **导出数据**：一键下载 JSON 备份文件
- **导入数据**：选择 JSON 文件恢复
- 关于说明

### PWA 特性
- `manifest.json`：应用名"我的菜谱"、图标、主题色
- Service Worker：缓存所有静态资源，离线可访问
- 添加到主屏幕后全屏显示，无浏览器地址栏

## 八、实施步骤

1. **创建项目骨架**：`index.html` + 目录结构 + `manifest.json` + `sw.js`
2. **数据库层**：`js/db.js`（Dexie.js 初始化，dishes/meals 两张表，CRUD 方法）
3. **初始数据**：`data/initial-dishes.json` + `js/init-data.js`（首次启动导入）
4. **样式**：`css/style.css`（移动优先，底部 Tab，卡片列表，表单）
5. **路由与主框架**：`js/app.js`（hash 路由，Tab 切换，视图容器）
6. **菜品列表页**：`js/dishes.js`（搜索、筛选、列表渲染、点击进详情）
7. **菜品详情页**：`js/dishes.js`（展示信息 + 做菜笔记历史 + 添加笔记 + 编辑）
8. **新增菜品页**：`js/add-dish.js`（表单 + 抖音提示词辅助 + 图片上传压缩）
9. **每日菜单页**：`js/meals.js`（日期选择、添加/移除菜品、历史记录）
10. **设置页**：`js/settings.js`（统计、导出/导入 JSON）
11. **PWA 配置**：`manifest.json` + `sw.js` + 图标
12. **本地测试**：用 `python -m http.server` 或类似方式启动，手机访问验证

## 九、假设与决策

1. **不做营养计量计算**：用户选择"只记菜品不计量"，营养目标仅作参考展示
2. **不做多设备自动同步**：用户选择"本地+导出备份"，通过手动导出/导入 JSON 实现
3. **抖音视频不自动提取**：抖音不开放个人 API，采用"提示词辅助"工作流（复制提示词 → 豆包 → 粘贴回）
4. **图片压缩**：上传图片时自动压缩到最大宽度 800px，避免存储溢出
5. **首次启动自动导入初始菜品清单**
6. **不创建 README.md**（除非用户要求）
7. **PWA 图标**：使用简单的文字图标（菜谱/餐具 emoji 风格），后续可替换
